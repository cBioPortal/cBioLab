# Demo: cbio-lab as the referee for AI hypothesis generation

Five minutes. The point to land: **an AI makes proposing hypotheses cheap; this tool makes
testing them honest.** Every step below is something a chatbot writing pandas against an
export cannot do on its own.

Two campaigns are prepared on msk_chord_2024:

| campaign | state | use it to |
|---|---|---|
| NSCLC — early immunotherapy failure vs durable response | complete | walk through a finished result |
| Colorectal — early progression on first chemotherapy vs durable control | draft, 12 hypotheses | lock and run live (~40 s); nobody knows the answer in advance |

Both were generated by Claude acting as the generator over MCP (`campaign_create` →
`campaign_register`). In the room, the generator is the Claude sidebar in Chrome, driving the
page's own tools (see the variant below); the campaign engine never calls a model itself.

## Script

**1. The question** (`/campaign`, 20 s). A researcher asks in plain words. The four boxes at the
top are the whole method: you ask, AI proposes, lock in, the tool referees.

**2. The hypotheses** (open the colorectal draft, 60 s). Each card is a claim in plain language,
but underneath it is a precise analysis document — *open the analysis* shows the exact cohorts.
Point out:
- **Tests: one thing.** Each hypothesis declares the single number that decides it and which way
  it should go. Six genes in one chart would be six tests nobody counted.
- **Patient counts, not results.** The engine has already checked every document against the
  study's real vocabulary and counted the patients in each group — on the discovery half only,
  from cohort definitions alone. Nothing about the outcome has been seen.
- **Untestable is said out loud** (the NSCLC campaign has two: MSI-high NSCLC has 10 patients;
  the researcher's never-smoker idea has 21 durable responders). A literature-only generator has
  no idea what data exists.
- *remove* works until the lock, and never after.

**3. Lock in** (click it, 20 s). The list is timestamped and hashed. From here the database
itself — triggers, not app code — refuses any addition, removal or rewording. This is what lets
the report say "1 of 12 tested" and mean it.

**4. Run** (click it, ~40 s). Talk over the spinner: each hypothesis runs on the **discovery
half**; one correction is applied across all of them; only survivors are re-run, unchanged, on
the **validation half** — patients nothing so far has touched. Which half a patient is in is
decided inside the database by a hash of their id, so no one, human or AI, can choose it.

**5. The report** (switch to the NSCLC campaign if the live run is dull, 90 s).
- The headline: **8** "discoveries" an AI reporting p < 0.05 would have claimed → **4** held up.
- *Held up*: STK11 (21.9% vs 10.2% of patients altered, then 21.4% vs 13.5% on held-out patients), lower TMB,
  higher copy-number burden, PD-L1 status — all consistent with the literature.
- *Failed replication* is the best part: KEAP1 looked real (p = 0.037) and vanished on held-out
  patients (p = 0.69). So did ARID1A, smoking status, and the STK11 survival effect. A chatbot
  on its own would have reported every one of them.
- Every number links to the analysis that produced it — cohort definitions, the compiled SQL,
  a live re-run — for the discovery and the validation half separately.

**6. Close** (20 s). Nothing here chose what to test. The generator can be as creative as it
likes because the tester cannot be persuaded: fixed halves, one correction, a frozen list, and
failures kept on the record.

## Variant: the Claude browser sidebar as the generator

The campaign page exposes every step as a tool, so a browser agent can be the generator while
the audience watches the page fill in:

- **WebMCP** — registered with `document.modelContext` (`navigator.modelContext` before
  Chromium 150) as `campaign_get`, `campaign_format`, `campaign_vocabulary`,
  `campaign_check_hypothesis`, `campaign_register`, `campaign_remove`, `campaign_lock`,
  `campaign_run`, `campaign_report`.
- **`window.cohortLab`** — the same functions as a page global (`getFormat()`,
  `registerHypotheses([...])`, `lock()`, `run()`, `report()`, …), because as of mid-2026 the
  Claude in Chrome extension does not *discover* WebMCP tools on its own, but can call them
  when told to run page JavaScript (anthropics/claude-code#76809).
- The **"For AI agents"** panel at the bottom of the page says all of this in plain text — that
  is how the sidebar finds out — and has a JSON paste box for an agent that only types.

Start on `/campaign` with the sidebar open: its "Start a campaign" prompt has the sidebar call
`createCampaign(question)`, which opens the new campaign's page and its tools. Or, on an
existing draft, ask the sidebar something like: *"Read the For AI
agents section of this page. Use window.cohortLab to read the hypothesis format and the study
vocabulary, write 10 hypotheses for this question, check any you are unsure of, and register
them. Stop before locking."* Then lock and run it yourself, or tell it to once you have looked
at the list.

## Running it yourself

- In the app: `/campaign` → start a question → copy the page's prompt into the Claude sidebar
  (or paste hypothesis JSON into the "For AI agents" box) → review → lock → run. The campaign
  engine never calls a model itself; the sidebar is the generator.
- From any MCP client connected to `/api/mcp`: `campaign_create`, `campaign_check_hypothesis`,
  `campaign_register`, `campaign_lock`, `campaign_run`, `campaign_report`. The hypothesis format
  is in `campaign_create`'s reply; the document grammar in `describe_dsl`.

## What to say if asked

- *"Isn't half the data less power?"* Yes — that is the price of a replication you can trust
  from one dataset. The funnel shows it: survivors must clear p < 0.05 again on ~900 patients.
- *"Can an agent cheat by opening many campaigns?"* Today, yes — there is no identity, so the
  ledger counts per campaign. Counting everything one identity ever ran is the next step.
- *"Why not replicate on another institution?"* Federation already runs the same document
  across instances; making it the campaign's replication target is a parameter, not a redesign.
  Timeline data is mostly MSK-only, which is why the held-out half exists.
