# Results View inventory (RV-)

- **Area:** Results View (`/results/<tab>`): query summary, 11 visible tabs (Oncoprint ... Download) plus a retired Network tab, URL contract, plus the query-form pieces that define what a query can express (OQL, profiles, case sets).
- **Source paths:** `cbioportal-frontend/src/pages/resultsView/**`; tab bodies that live elsewhere: `src/shared/components/oncoprint/**`, `src/shared/components/plots/**`; query form: `src/shared/components/query/**`, `src/shared/components/GeneSelectionBox/**`, `src/shared/lib/oql/**`; shared settings/banners: `src/shared/alterationFiltering/**`, `src/shared/components/driverAnnotations/**`, `src/shared/components/banners/**`; routes `src/routes.tsx`.
- **Size (non-spec .ts/.tsx):** `pages/resultsView` 91 files / 37,986 lines (store alone `ResultsViewPageStore.ts` 6,013); `shared/components/oncoprint` 17 / 13,637; `shared/components/plots` 24 / 20,036; `shared/components/query` 39 / 10,610; OQL lib 3 / 1,833 (incl. generated parser).
- **Features listed:** 122 (RV-001 ... RV-122).
- **With E2E coverage:** 99 (rows whose E2E column is not `none`). Coverage is by spec file name relative to `end-to-end-test-playwright/tests/` (`.spec.ts` omitted; `local/` = Playwright local-DB lane); "screenshot-results-*" means the three suites that call `runResultsTestSuite` in `helpers/results-screenshots.ts` (no-session URL, session URL, excluding-unprofiled URL), which load oncoprint, igv, cancer type summary, mutex, plots, mutation, coexpression, comparison (overlap, clinical, alterations, mRNA), survival, pathwaymapper and data_download tabs and take screenshots.

## Open questions

1. **Oncoprint default column mode.** `ResultsViewOncoprint.columnMode` treats a missing `show_samples` as patient, while `oncoprintAnalysisCaseType` falls back to `oncoprint_defaultview` (default `patient`); are both read by the same UI, and what happens when the server config says `sample`?
2. **Heatmap and generic-assay URL formats.** `generic_assay_stacked_profiles`, `_absolute_profiles`, `_sortby`, `_bar_profiles` serialization is in `ResultsViewOncoprint` helper methods that were not fully read; the exact grammar and limits (max entities per heatmap group, max groups) are unknown.
3. **Oncoprint track and drag-select menus** live in the `oncoprintjs` package (not in this repo), so the full list of per-track options (sort, gaps, clustering, edit colours) and selection actions was inferred from the handlers that call into it.
4. **Mutations/SV/Comparison sub-features in other inventories.** The mutation mapper (lollipop, 3D viewer, table), the enrichment tables, the survival chart and the Overlap/Clinical sub-tabs are shared with Group Comparison, Patient View and the Mutation Mapper tool; confirm which inventory (RV vs GC vs PV) owns the detailed rows to avoid double counting.
5. **Structural Variants tab has no E2E coverage**, and the Generic-assay comparison sub-tabs, NDEx, Jupyter/Oncoprinter hand-off, MutSig/GISTIC pickers and Download-tab "Query"/virtual-study buttons are also unexercised; decide whether the modernization needs parity tests first.
6. **Custom case list in the URL:** `case_set_id=-1` with no `case_ids` is read as a literal sample list id `-1` (RV-008); is a posted query with `-1` and an empty `case_ids` ever produced, and what error should the modernized query give?
7. **Settings persistence.** Driver annotation choices (OncoKB, hotspots, custom tiers, VUS) are not in the URL, while germline exclusion and hide-unprofiled are; are shared links expected to reproduce annotation choices (the bookmark hash carries only clinical tracks)?
8. **Gain/Shallow Deletion rendering.** The oncoprint legend includes Gain and Shallow Deletion but the default OQL only requests AMP and HOMDEL; confirm when these appear (only with explicit `GAIN`/`HETLOSS`/`CNA>=GAIN` OQL?) because cBioLab rejects those tokens.
9. **External services.** OncoKB, 3D Hotspots, Genome Nexus, CIViC, NGCHM (MD Anderson), NDEx iQuery (UCSD) and PDB/AlphaFold are called directly from the browser; exact endpoints were not enumerated here and cBioLab's version-pinned OncoKB model differs from the portal's live annotation.
10. **`comparison_selectedEnrichmentEventTypes` is flagged as a session property** (stored remotely when the URL is long) while the other `comparison_*` view params are not; is that intentional?
