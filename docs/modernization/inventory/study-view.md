# Study View inventory (ID prefix SV-)

- **Area**: Study View (`/study`, `/study/<tab>`): single, multi-study and virtual-study cohort dashboard of charts, tables, filters, groups and downloads.
- **Source paths** (under `cbioportal-frontend/src/`): `pages/studyView/**`; shared parts it imports: `pages/groupComparison/comparisonGroupManager/**`, `shared/components/resourceTable/**`, `shared/components/resourceViewer/**`, `shared/api/resourceTableClient.ts`, `shared/components/embeddings/**`, `shared/components/plots/PlotsTab*` (Plots tab), `shared/components/driverAnnotations/SettingsMenu.tsx`, `shared/components/MSKTabs/**`.
- **Size**: `pages/studyView` = 69 non-spec TS/TSX files, 47,198 lines (`StudyViewPageStore.ts` alone 13,253; `StudyViewUtils.tsx` 5,719; `StudyViewPage.tsx` 1,434) plus 11 spec files; the shared parts above add about 12,000 lines. E2E reviewed: `end-to-end-test-playwright/tests/studyview.spec.ts` (1,383 lines), 7 `local/study-view*`/`virtual-study`/`group-color-chooser`/`struct-var-table` specs, and the study-view parts of 10 more specs.
- **Features listed**: 109
- **With E2E coverage**: 78 (a row counts when its E2E cell names at least one spec, including specs that only touch it, such as screenshot or "download hidden" checks; the Notes column says when coverage is partial)

Conventions: endpoint names are `CBioPortalAPIInternal` / `CBioPortalAPI` methods from `packages/cbioportal-ts-api-client` unless marked "axios" (resource-table calls in `shared/api/resourceTableClient.ts` are plain axios, not generated). `StudyViewFilter` means the JSON body most data endpoints take (see SV-021). E2E paths are relative to `end-to-end-test-playwright/tests/`. cBioLab column: "Explore" = the Explore tab of `/lab` (`app/lab/explore-sections.tsx`, `use-explore*.ts`, `explore-charts.tsx`); `lib/views/<kind>` names are view kinds. Where a cBioLab match is only a guess it is marked `?`.

## Open questions

1. **Clinical data downloads.** `getAllClinicalDataByStudyViewFilter` uses `pageSize | 500` (bitwise OR, probably meant `||`), so the SV-087 download asks for 25,084 rows per page while computing the page count with 25,000; and the Clinical Data tab's own download (`downloadDataFetcher`) requests only 500 rows. Should the rebuilt study view download every selected row in both places, and is the first behaviour a bug to reproduce or to fix?
2. **Filters are not in the URL.** Applied filters live only in memory; the shareable filtered link is the bookmark button (`#filterJson=`) or a virtual study. Does cBioLab want the same split, or should every filter live in the document/URL (`?doc=`) so back/forward and refresh keep it?
3. **Patients vs samples.** The study view shows both counts but every chart filter selects samples; patient count is derived from the selected samples in the browser, and patient-level attributes (e.g. survival) are counted per patient while sample attributes are counted per sample. Which unit should the Explore page present as primary (cBioLab Explore counts patients), and how should mixed-unit charts be labelled?
4. **Session-service-dependent features.** Groups, saved chart settings, custom data and virtual studies depend on the session service and login (`ServerConfigHelpers.sessionServiceIsEnabled()`), and have almost no E2E coverage without the local login spec. Which of these must be in the first cBioLab release, and what replaces the session service (`app/_saved`, `app/groups`)?
5. **Which dead or special-cased code to drop.** Candidates found: `ChartTypeEnum.MRNA_VIOLIN_PLOT` and `SpecialChartsUniqueKeyEnum.MRNA_VIOLIN_PLOT` (no meta creator), the `openResource_<id>` legacy tab, the hard-coded `heme_onc_nsclc_genie_bpc` left-truncation and `msktarget` default violin, the MSK hostname priority table, the embeddings JSON URL, and the MD Anderson heatmap iframe. Which are product features to keep?
6. Do the Alteration Filter settings (driver, germline/somatic, tiers) affect only the gene tables, or also gene-specific charts and survival? The code sends `alterationFilter` in the shared `StudyViewFilter`, but no spec checks pie/bar charts under it.
7. Is the NA slice part of the pie percentage denominator (SV-018)? The code divides by the sum of returned counts; whether the server includes an NA count for every attribute was not checked in the backend.
