How an analysis request is processed

From an edit on the analysis page to a figure in a card. The oncoprint follows the same path, apart from the grey notes.

Browser

1
The page sends the document
app/lab/page.tsx → hooks → doc-store.ts changes the document
use-analysis.ts (React Query) → api.ts → POST /api/analysis?oncoprint=spec
Only the document JSON is sent. Clients never send SQL.
↓document JSON

Server

2
The route
app/api/analysis/route.ts: parseBody (lib/api-schemas.ts) → withRequestCustomData
cachedAnalysis (lib/next-cache.ts): a cached result, or run the engine
Uploads and stored id sets are attached here.
3
The engine: runAnalysis(doc) in lib/analysis.ts
upgrade the doc, fill in params, expand splits
for each cohort × study:
resolverFor(study) (lib/federation.ts)
res.cohortSql(def) → compileCohortDef (lib/cohort2.ts; oql.ts, compiler.ts)
count it in ClickHouse (lib/ch.ts)
for each view: viewRunner(kind) (lib/views/index.ts) → lib/views/<kind>/run.ts
SQL, layer 1: a cohort definition is compiled to SQL here, once per study.
4
The view's runner: lib/views/<kind>/run.ts
asks the resolver for numbers, e.g. res.geneCounts(cohort, genes)
the view's query wraps the cohort SQL as a subquery, then runs on ClickHouse (a peer instance gets an HTTP call instead)
computes the statistics and its method record (method.ts)
returns a ViewResult: plain JSON numbers, with no JSX and no SVG
Oncoprint: lib/oncoprint.ts fetches rows → oncoprint-assemble.ts (pure) → the "contract" JSON
SQL, layer 2: the view's aggregate query, built in the kind's sql.ts, or in lib/federation.ts / federation-views.ts.
↓result JSON: numbers, method, queries, provenance

Browser

5
Cards and figures
app/lab/view-cards.tsx: one card per view, chosen by kindUi(kind) → app/lab/kinds/<kind>.tsx
shared card (kind-cards.tsx): header + the kind's Controls + <ViewFigure>
<ViewFigure> (app/lab/figure.tsx) → viewToSvg(result) (lib/view-svg.ts)
→ lib/views/<kind>/figure.ts returns an SVG string (laid out with lib/chart/) → placed in the card at its width
Oncoprint: its own Card → app/_oncoprint/OncoprintCard.tsx → OncoprintFigure draws the contract on a canvas
JSX lives only in app/lab/: the cards, plus each kind's kinds/<kind>.tsx.
Figures are pure functions from result JSON to SVG. MCP calls the same figure.ts on the server (?figures=svg).
